# HiddenNotch

*[English](README.md)*
*[변경 이력](CHANGELOG.md)* · *[릴리즈 방법](docs/RELEASING.md)*

MacBook 메뉴바 배경을 검게 유지해 노치가 눈에 띄지 않게 하는 초경량 macOS 앱입니다.

외부 모니터를 연결하거나 해제하실 때, 배경화면을 바꾸실 때, 잠자기에서 돌아오실 때,
재부팅하신 뒤에도 손대실 필요 없이 상태가 그대로 유지됩니다.
앱은 584KB, 상주 메모리는 42MB입니다. Dock 아이콘 없이 메뉴바에만 있습니다.

## 동작 방식

배경화면 파일은 건드리지 않습니다. 노치가 있는 화면의 상단 메뉴바 영역에 검은 패널을
**배경화면 바로 위, 나머지 모든 것의 아래**(`kCGDesktopIconWindowLevel + 1`)에 깔아 둡니다.
메뉴바 자체가 반투명이라 그 뒤가 검으면 메뉴바 배경과 노치 양옆이 함께 검게 보이고,
메뉴바 글자와 아이콘은 그대로 보입니다.

레벨을 낮게 두는 이유는 메뉴바가 **없는** 상황 때문입니다. 미션 컨트롤과 전체화면 앱은
화면 맨 위까지 자기 UI를 그리는데, 패널이 그 위에 있으면 UI를 잘라먹습니다. 미션 컨트롤에서
데스크탑 썸네일의 윗부분이 잘리는 증상으로 나타났습니다. 메뉴바 영역은 원래 일반 창이
침범하지 못하는 자리라, 낮은 레벨에 두어도 평상시에는 가려지지 않습니다.

- 패널은 `ignoresMouseEvents = true`라 클릭을 가로채지 않습니다.
- 모든 Space에 참여하고(`canJoinAllSpaces`), Cmd-Tab과 Mission Control 순환에서 빠집니다.
- 오버레이 높이는 하드코딩하지 않습니다. 화면마다 safe area, 보조 영역, 실제 메뉴바 높이
  중 가장 큰 값으로 계산합니다. 화면마다 값이 다릅니다(측정한 예로 내장 33pt, 외부 30pt).
- 외부 모니터는 메뉴바가 있어도 `visibleFrame`이 줄어들지 않아 높이를 알 수 없습니다.
  그래서 메뉴바 창의 실제 좌표를 창 목록에서 읽어 보완합니다(`MenuBarProbe`).
  좌표와 소유자만 읽으므로 화면 기록 권한이 필요 없고, private API도 아닙니다.
- AppKit이 창을 메뉴바 아래로 밀어내는 기본 동작은 `constrainFrameRect`를 재정의해 끕니다.
  이 한 줄이 없으면 검은 띠가 메뉴바 높이만큼 아래로 내려가 앉습니다.

## 외부 모니터

기본값은 기획안대로 **노치 화면에만** 적용입니다. 메뉴에서 `외부 모니터에도 적용`을
켜시면 노치가 없는 외부 모니터의 메뉴바까지 검게 만듭니다. 기획안 §4의 기본값과
완료 기준 7번을 기본 상태에서 그대로 지키기 위해, 항상 켜 두지 않고 토글로 두었습니다.

이 설정은 `UserDefaults`의 세 번째 값(`applyToAllScreens`)이라 기획안 §9가 정한 두 값
원칙에서는 벗어납니다. 다만 화면 ID, 좌표, 해상도를 저장하지 않는다는 핵심 원칙은
그대로 지킵니다.

## 상태가 풀리지 않게 하는 장치

네 겹입니다. 하나씩만으로는 실패하는 경우를 확인했기 때문입니다.

1. **전체 재구성** — 화면 구성이 바뀌면 기존 창 프레임을 고쳐 쓰지 않고 전부 버린 뒤
   새로 만듭니다. 다만 이미 상태가 맞으면 손대지 않습니다. 재구성 과정에서 키 윈도우가
   바뀌면 열려 있던 메뉴가 함께 닫히기 때문입니다(1.2에서 고쳤습니다).
2. **지연 재확인** — 외부 모니터를 연결하신 직후 macOS는 화면 목록과 좌표를 한 번에
   확정하지 않습니다. 즉시 적용한 뒤 0.5초, 1.5초, 3초에 다시 확인합니다.
   몰려 오는 이벤트는 debounce합니다.
3. **Watchdog** — 15초마다 화면 수, 오버레이 수, 프레임 일치 여부를 값 비교만으로
   점검하고 어긋나면 스스로 재구성합니다. 이벤트 알림을 놓쳐도 복구됩니다.
4. **캐시 없음** — 화면 ID, 좌표, 해상도는 저장하지 않습니다. `UserDefaults`에 있는 값은
   `isEnabled`와 `launchAtLoginRequested` 둘뿐입니다.

## 로그인 시 자동 실행

`SMAppService.mainApp`을 씁니다. macOS가 사용자 승인을 요구하는 상태(`requiresApproval`)가
되면 메뉴에 "로그인 항목 승인 필요" 항목이 나타나고, 선택하시면 시스템 설정의 로그인 항목
화면이 열립니다.

ad-hoc 서명 상태(개발 빌드)에서는 등록이 실패할 수 있습니다. 실제 자동 실행을 확인하실
때는 `/Applications`로 옮기신 뒤 보시는 편이 안정적입니다.

## 확인된 것과 남은 것

실기(노치 내장 화면 + 외부 모니터 연결)에서 확인했습니다.

- 노치 화면만 대상으로 잡고 외부 모니터에는 오버레이를 만들지 않습니다.
- 오버레이가 내장 화면 상단에 정확히 1470×33으로 놓입니다(메뉴바 영역과 일치합니다).
- 유닛 테스트 16개가 통과합니다.

직접 눈으로 확인이 필요한 항목입니다(기획안 Phase 0 판정 기준).

- 메뉴바 글자와 아이콘이 가려지지 않는지
- 전체화면 앱에서 상단 콘텐츠를 덮지 않는지 — 화면이 보고하는 메뉴바/safe area 값이
  0으로 떨어지면 오버레이가 자동으로 사라지도록 되어 있습니다. 다만 macOS 버전에 따라
  값이 유지될 수 있어 실사용 확인이 필요합니다.
- 메뉴바 자동 숨김 설정에서의 동작
